Workflow

  1. Load a local ROM and record the header information and hash in your research notes.
  2. Run the Japanese-text candidate scan to locate likely uncompressed dialogue or menu text.
  3. Run the ROM-pointer scan to identify candidate pointer tables and nearby targets.
  4. Enter a provisional .tbl mapping when you learn the game’s encoding.
  5. Use the hex and decode panels to compare hypotheses against observed game text.
  6. Validate every conclusion in an emulator before building an extractor, inserter, or patch pipeline.

This tool does not identify compressed text, custom script engines, variable-width fonts, or control codes automatically. It is intended to reduce the initial reconnaissance workload.

2. Japanese Text Candidate Scan

Searches for runs of plausible Shift-JIS-style double-byte characters. Results may include false positives, graphics data, compressed data, or unrelated tables.

3. ROM Pointer Scan

Looks for aligned 32-bit little-endian values that point into the conventional GBA ROM address range. A hit is not proof of a text pointer: it may point to code, graphics, data, or a table.
